## 3. REST API

- Кількість сторінок: `42` (при `limit = 100`)
- `total_count`: `4158`
- Отримано подій (`received`): `4158`
- Унікальних подій (`unique`): `4143`
- Дублікатів у вхідному потоці (`duplicates_in_input`): `15`
- Тимчасові збої під час запуску:
  - На першій сторінці (`offset = 0`, без курсора) перша спроба `GET /api/v1/delivery-events` отримала статус `HTTP 429 Too Many Requests` із заголовком `Retry-After: 1`; після очікування `max(backoff=1, Retry-After=1) = 1.0 с` повторна спроба (#2) завершилася успішно (`HTTP 200 OK`).
  - На другій сторінці (`offset = 100`, `cursor = c100`) перша спроба отримала статус `HTTP 500 Internal Server Error`; після експоненційної паузи `backoff = 1.0 с` повторна спроба (#2) завершилася успішно (`HTTP 200 OK`).
- Робота retry, backoff і `Retry-After`:
  - У функції `request_page` для тимчасових збоїв (`429`, `500`, `502`, `503`, `504`, `Timeout`, `ConnectionError`) виконується до `max_attempts = 4` спроб із розкладом затримок `1, 2, 4` секунди (`2 ** (attempt - 1)`).
  - При `HTTP 429` зчитується заголовок `Retry-After`, перевіряється його цілочисельність і невід'ємність, а фактична затримка обчислюється як `max(backoff, int(Retry-After))`. Якщо затримка перевищує `30` секунд або заголовок некоректний, піднімається `ValueError`.
  - Для постійних помилок (`400`, `401`, `403`, `404`, `422`), редіректів (`301`, `302` за рахунок `allow_redirects=False`) та `SSLError` повторні спроби не виконуються. Секрети (`X-API-Key`, повний DSN) у логи не виводяться.
